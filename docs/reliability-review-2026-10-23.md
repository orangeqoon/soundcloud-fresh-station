# FreshDig の調査と改善計画

調査日: 2026-10-23。対象: v2.1.4 を基点とする拡張機能と UserScript。既存の未コミット変更を保持して調査した。

## 目的と優先順位

FreshDig の目的は、SoundCloud で未知の作者を連続して発掘し、気になる作者を後で聴けるようにすること。
優先順位は「ユーザーの再生・停止操作が確実に伝わる」「既知・除外した曲を誤って流さない」「追加通信を増やさない」「動作条件がUIから分かる」とする。

## コードから確認できた原因

| 問題 | 確認できた構造 | 改善方針 |
| --- | --- | --- |
| ロボット確認中にも追加通信が進む | API の停止判定が送信待ちの前だけで、待機後に再確認しない | 送信直前の停止判定、送信処理の直列化、回復確認の多重起動防止 |
| ロボット確認の検出に差がある | XHR と fetch の観測に差がある | 既知のチャレンジ応答を観測して拡張機能の通信を止める |
| 自動ミニプレイヤーが使えるように見える | Document PiP の存在だけを対応判定に使用している | Media Session の登録可否、ブラウザーが実際に起動したか、失敗理由を区別 |
| 再生ボタンを押しても反応が分からない | 別タブへの命令で、処理実行前に完了応答を返す | 実行と結果の確認後に応答する |
| 止まった音声を再開できない可能性 | 古い音声要素を参照する経路と、失敗確認の弱いフォールバックがある | 現在の再生対象を選び、再開結果を確認。ユーザーの一時停止を勝手に解除しない |
| Like の表示が戻ることがある | サイトの更新完了前に、古いDOMでウィジェット側の状態を上書きする | 操作対象IDごとの処理中状態と成功・失敗の照合 |
| 「後で聴く」が Dig に反映されない | 保存処理はあるが、除外判定に渡していない。ステーション候補にも独自の判定経路がある | 通常の曲切替とステーション候補の両方で作者IDを照合 |
| 設定変更が他タブに遅れて反映される | 拡張ストレージの変更通知が「後で聴く」専用だった | Dig 等の設定変更も既存ブリッジで通知 |

上記はソースから確認できた不備。ユーザー環境で起きる長時間再生停止や SoundCloud の判定には、通信、サイトの内部実装、ブラウザーの省電力・再生許可なども関係するため、模擬テストの合格だけで完全解消とは判断しない。

## 自動ミニプレイヤーの条件

通常の Document PiP 起動には、ページ上でのクリックなど、一時的なユーザー操作が必要。
タブ切替での自動起動は Media Session の `enterpictureinpicture` をブラウザーが呼び出す経路を使う。
音声付き再生、音声フォーカス、サイトの許可、ブラウザーの対応などが関係する。
したがって、チェックをONにするだけで常に開く機能とは説明できない。`visibilitychange` で強制的に開く設計は採用しない。

- [Chrome: メディア再生の自動PiP](https://developer.chrome.com/blog/automatic-picture-in-picture-media-playback)
- [Chrome: Document PiP](https://developer.chrome.com/docs/web-platform/document-picture-in-picture/)
- [Document PiP 仕様](https://wicg.github.io/document-picture-in-picture/)
- [Media Session 仕様](https://w3c.github.io/mediasession/)

検証に使ったローカル Edge は `155.0.4283.62`。ただし、普段利用しているブラウザープロファイルのサイト権限・自動PiPの提供状態は確認していない。インストール済みのバージョンだけで、自動起動の可否は断定しない。

## 初回案内の仕様

新規インストール後、SoundCloud を最初に開いたときに3パネルで説明する。更新だけでは再表示しない。

1. **ミニプレイヤー**: 何ができるか、拡張機能のアイコンとページ内の 🪟 ボタンから開けることを示す。
2. **Dig と ⏭️**: Dig のON/OFFと、ウィジェットの ⏭️ が単なる「次へ」ではなく曲を不再生リストに登録する操作であることを説明する。
3. **後で聴く**: 🧐 は作者を保存すること、拡張機能アイコンを開くとリストが見えることを説明する。保存した作者を聴くときは Dig をOFFにする。

ブラウザーの拡張機能アイコン自体はページから強調できないため、ページ内ボタンを案内し、ツールバー側の場所は文章で説明する。

## 「一度聴いた曲を二度と聴かない」モード — 設計のみ

今回は実装しない。

### 推奨する保存先

拡張機能のサービスワーカーが管理する **IndexedDB** を第一候補にする。
キーは `[SoundCloud のアカウントID, 曲ID]`。値は再生済み日時など最小限とし、曲名、画像、音声、トークンは保存しない。
UserScript 版で同等機能を提供する場合は SoundCloud オリジンの IndexedDB となり、拡張機能版とは保存場所・消去条件が異なることを明示する。

全件を `Set` や `localStorage` に読み込まない。直近の照合結果だけを小さなLRUキャッシュ（例: 2,000件）に保持し、キューの先読み時に IndexedDB をまとめて照合する。
保存・照合に SoundCloud API は使わない。複数タブには「曲IDが再生済みになった」というイベントのみ通知し、定期的な全件同期は行わない。

### 「聴いた」の定義

最初の案は、実際に音声が進んだ時間を積算し、「30秒、または曲長の50%の短いほう」を満たした時点で1回だけ記録する。
一時停止、バッファ待ち、シークで飛ばした区間は積算しない。曲のロードだけ、自動除外だけでは記録しない。
最終仕様はユーザーが選べる基準にし、短い曲、途中から再生した曲、ライブ音源もテストする。

### メモリ制限と「二度と」の違い

メモリは小さく固定できるが、正確な永久履歴のディスク使用量は曲数に比例して増える。
「何曲でも永久に正確に除外」と「保存件数に上限を設けて古い記録を削除」を同時には保証できない。

- **永久履歴を優先**: 自動削除しない。容量表示、履歴の書き出し・読み込み、明示的な削除、保存失敗の通知を提供する。
- **容量を優先**: 180日・5万曲などの上限をユーザーが選ぶ。この場合、UIは「一定期間は再生しない」と説明し、永久除外とは呼ばない。

容量はブラウザーの実測で決める。曲IDそのものが小さくても IndexedDB のインデックス等の管理領域があるため、単純に「IDのバイト数 × 曲数」では見積もらない。
Bloom filter は少ない容量で済むが、未聴曲を誤って除外する可能性があり、「未知の曲を発掘する」という目的に合わないため初期案では使わない。

ブラウザーのデータ消去、プロファイル変更、保存容量不足で履歴が失われ得る。別端末への自動同期は別の機能であり、初期案には含めない。

- [IndexedDB 仕様](https://w3c.github.io/IndexedDB/)
- [BroadcastChannel 仕様](https://html.spec.whatwg.org/multipage/web-messaging.html#broadcasting-to-other-browsing-contexts)

## 全体監査で残る改善点

### 優先度が高いもの

- **アカウント別キャッシュ**: 現在の Likes・Follow・プロフィールのキャッシュはアカウント別の名前空間になっていない。アカウント切替時に古い除外状態を流用しないよう、所有者IDの照合と移行・破棄の手順が必要。
- **サイト内部への依存**: webpack、非公開API、CSSセレクターの変更で操作できなくなる可能性がある。内部アクセスのアダプターを分離し、機能ごとの対応状況とフォールバックを診断に出す。
- **長時間の実環境検証**: 曲の終了、広告、通信断、タブの省電力、ページ遷移、複数タブを含む連続再生試験が必要。実際のロボット確認は手動で解消し、復帰後の挙動を確認する。
- **全件同期の負荷**: Like・Follow・Repost の大量取得は、送信間隔を守っても時間がかかる。差分イベントを優先し、全件同期は不足時・明示同期に寄せる。サイト本体の通信は拡張のリミッターでは制限できない。
- **複数タブの通信予算**: 全件同期のロックとは別に、プレイリスト・作者情報・resolve の送信予算をタブ共通にする余地がある。今回のタブ内直列化だけで、ブラウザープロファイル全体の総通信数が固定されるわけではない。

### 次に整えたいもの

- `station_hook.js` に通信・除外・プレイヤーUI・サイトアダプターが集中している。まず振る舞いをテストで固定し、その後に小さく分離する。
- **UserScript 版の機能差**: 「後で聴く」の保存は拡張のブリッジとサービスワーカーに依存している。単独 UserScript での保存先・初回案内を別途設計し、拡張版と同じ機能だと誤解させないようにする。
- 連続スキップの安全弁は、無限ループ防止と不再生ルールの一貫性を両立する必要がある。「除外曲を強制再生する」より「候補不足を表示してDigを一時停止する」設計を検討する。
- サイト側の成功を確認せず見た目のクラスだけを変える同期は避ける。成功した操作イベントを主とし、DOMは現在の曲・作者と一致する時だけ補助的に読む。
- 診断レポートでは、停止原因を「手動停止」「通信待ち」「再生許可」「キュー不足」「確認待ち」「命令失敗」に分ける。認証情報は含めない。

## 検証の区別

Node テストは純粋処理と模擬ブラウザーの回帰確認、ヘッドレスブラウザーは表示とイベント処理の確認に使う。
これらは、実アカウントでの長時間再生、実際の自動PiP、サイトの最新UIとの同期確認の代わりにはならない。

## v2.2.0 で反映した変更と確認結果

- API の送信処理をタブ内で直列化し、送信待ちの前後で停止状態を確認。API側の確認待ちフラグが残っている間も通常通信を止める。
- サイト側 fetch の既知の確認応答も検出。手動確認の画面が消えた後の確認リクエストは1本だけにし、通常の成功応答からも復帰できるようにした。
- 自動スキップに最低750msの間隔を追加。既存の連続スキップ時の待ち時間も維持。
- 現在の音声要素を選び、DOMに挿入されない正規の音声要素も扱う。再生操作の成功・失敗を確認し、未解決の再生要求はタイムアウトする。
- 停滞・自然終了時の復帰は、再生を継続する意図がある場合だけ、同じ曲について最大2回。バッファ待ち中を含め、手動停止後に勝手に再開しないようにした。
- 別タブへの操作は受領通知と処理完了通知を分離。処理中の同じ操作を重複送信しない。完了が不明な場合はその旨を表示し、自動で再送しない。
- Like・Repost・Follow は、対象の曲が一致する安全なネイティブ操作を優先し、DOMの更新を待ってキャッシュと他タブへ反映。無関係なページのFollowボタンは読み取らない。
- Follow/Repost で対象が確認できるネイティブボタンがない場合は既存のAPI経路を使う。この場合、サーバー応答は確認するが、ページ側UIの即時反映までは保証していない。
- 「後で聴く」作者をDig中の曲切替・ステーション候補から除外。Dig OFFでは除外しない。
- 初回3パネル案内、再表示用の「使い方」、ページ上のミニプレイヤー入口、Digの状態強調、📡アイコンを追加・調整した。
- 音量操作のフォールバックも確認し、内部モジュールがない場合はサイト本体のコントロールを使う。適用を確認できなければ成功表示を出さず、本体での操作を案内する。音声要素のvolumeには直接書き込まない。

回帰テストは49件（指定の3ファイル27件、追加のブリッジ1件・ランタイム21件）。4言語のポップアップ、初回案内3パネル、再表示・完了記録、キーボード操作、幅320pxの表示も模擬Chrome APIを使ったヘッドレスEdgeで確認した。

既存ユーザーは拡張機能とSoundCloudページを再読み込みして反映する。「使い方」から案内を再表示できる。新規インストール後は初回表示し、バージョン更新だけでは案内を繰り返さない。

## v2.2.1 の追加変更と確認結果

- 「後で聴く」に保存した作者のプロフィール・tracks・個別トラックページでは、その作者の曲に対するDigの自動除外を一時停止する。Digの保存設定はONのまま保持し、別の作者や通常の発掘へ戻ると除外が働く。
- ページ移動で予約済みの自動スキップを取り消す。拡張側が一時停止した同じ曲だけを復帰対象とし、途中で利用者が停止した場合は勝手に再開しない。
- ミニプレイヤーの上段に「後で聴くリスト」、電波塔のステーション、輪郭の明瞭なフォローアイコン、作者除外を配置。下段の「🧐」は再生中の作者を保存する。上段のリストはミニプレイヤー内で開き、作者のtracksページへ移動できる。
- 拡張ポップアップからステーション開始・音量操作を削除。Dig Configを強調し、診断レポート保存を最下段へ移動した。
- サイトの再生バーはDigをツルハシ、ミニプレイヤー入口をオレンジ背景のラジオに変更。プレイリスト追加は「⋯」内へ移動し、塗りつぶしを解除した。

指定テスト28件、追加runtime/bridgeテスト24件の計52件が合格。UserScriptビルド、構文、4ファイルのバージョン一致、差分検査、変更ファイルを明示した一時Gitインデックスでのパス検査（StagedOnly、0件）、配置検査が合格した。実リポジトリーのステージ状態は変更していない。

模擬SoundCloudページを使うヘッドレスEdgeでは4言語、ポップアップの配置、バーのメニューとアイコン、ミニプレイヤーのリスト開閉・作者保存・試聴中表示・横幅を確認した。実アカウントでの長時間連続再生、実際の自動PiP許可・起動、SoundCloud本体との操作同期は別途実機確認が必要。ロボット検知の解消を保証するものではない。

元フォルダーへv2.2.1を反映し、配布ZIPを作成した。既存の未コミット変更は維持し、コミット・公開はしていない。

# FreshDig v2.2.2

## 変更点

- 拡張機能のポップアップに⏭️不再生リストを追加。曲名・作者名で検索し、登録を解除できます。
- 「🧐 後で聴くリスト」に表示を統一し、保存日の古い順に並べます。日付不明の項目は末尾です。
- ミニプレイヤー内のリストは見出しを固定し、リスト部分をスクロールできます。各作者の保存日と「×」解除ボタンを追加。保存日がない場合は「—」です。
- 「使い方を見る」は専用の拡張機能ページを開き、3つの説明をまとめて表示します。SoundCloudタブに古いスクリプトしかない場合でも案内を読めます。
- 発掘モードONは、サイトのバー・ミニプレイヤー・ポップアップで鮮明なオレンジを使います。
- マウスオーバーの説明を、ボタンの機能を示す短い文章へ変更しました。

## ガイド全文（日本語）

### 1. ミニプレイヤーを開く
FreshDigの一押し機能です。拡張機能アイコン、またはSoundCloudの📻から開けます。

### 2. Dig ONモード
ONにすると、不再生にした曲・Like済みの曲・フォロー中の作者の曲を飛ばします。

### 3. 🧐 後で聴くリスト
下段の🧐で作者を保存。拡張機能アイコンから一覧を開き、作者を選ぶとトラックページへ移動できます。

## 反映方法
使用中の拡張機能を再読み込みし、SoundCloudページを再読み込みしてください。開いているミニプレイヤーはいったん閉じてから開き直してください。

## 検証結果

指定テスト28件と追加runtime/bridgeテスト24件、計52件が合格。UserScriptビルド、JavaScript構文・JSON・バージョン一致、差分検査、StagedOnlyパス検査（変更9ファイル、検出0件）、配置検査も合格しました。

模擬SoundCloudページで、ポップアップ・バー・初回ガイド・ミニプレイヤーをヘッドレスEdgeで確認。4言語、40件のリスト、ホイール・スクロールバーのドラッグ、更新後のスクロール位置、保存日、解除成功・失敗時の表示、専用ガイドページを確認しました。実際のインストール済み拡張機能とSoundCloudでの操作は未確認です。
