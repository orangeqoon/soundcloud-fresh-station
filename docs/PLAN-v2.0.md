## 1. ユーザーの要望と方針（番号はユーザーの話の順）

### R1. ロボット確認（「ロボットですか」が出て聴けなくなる）
**結論（ユーザーにも伝えること）**: 確認画面そのものを自動で突破する仕組みは作らない（規約違反で、アカウント停止の危険もある）。代わりに**出にくくする**＋**出たらすぐ分かって、手で解いたら元に戻る**ようにする。SoundCloud は DataDome という不正アクセス対策を使っている可能性が高い（Sonnet が実際の画面で確認すること: `captcha-delivery.com` の iframe、または API の 403 応答に `x-datadome` ヘッダーや `captcha-delivery` の URL が入っているか）。

やること:
1. **同期は全タブで 1 回だけ**（E1）: `navigator.locks.request('freshdig-sync', { ifAvailable: true }, ...)` で 1 タブだけが同期する。最後の全件同期の時刻を localStorage（`soundcloud.com` の全タブで共有）に置き、**6 時間以内なら全件同期しない**。他のタブには `BroadcastChannel('freshdig')` で「キャッシュを読み直して」と知らせる。ポップアップの「🔄 同期」だけは強制。
2. **自分の API 呼び出しに上限**: `scApi()` の中で、前の呼び出しから最低 250ms 空ける、1 分あたり 60 回まで（値は定数に）。403 / 429 が来たら止まって待つ（60 秒→2 分→5 分と伸ばす）。`ensureCurrentTrackInfo` の `/resolve` 直呼び（`originalFetch`）と、ステーション補充の `originalFetch` も同じ上限を通す。
3. **スキップを減らす・間を空ける**（E2）: R5 の「先に飛ばす」で、スキップのたびに音声を読み込まないようにする。連続スキップは 5 曲を超えたら 1 回ごとに 1.5 秒空ける。
4. **ロボット確認を見つけたら止まる**: 確認画面（上の iframe / 403 応答）を見つけたら、自動スキップと自分の API 呼び出しを全部止め、ページとミニプレイヤーに「SoundCloud のロボット確認が出ています。ページで確認を済ませてください」と出す。確認画面が消えたら（iframe が消える・API が 200 に戻る）自動で再開。
5. やらないこと: 確認の自動突破、ブラウザの指紋や User-Agent の偽装、要求の発信元の偽装。

### R2. 言語の切替（日本語／英語）
途中まで入っている（未コミット）。仕上げる:
1. E4 の直書きの日本語を全部 `i18n.js` の辞書に移す（スキップ理由も。理由はキー `skipReasonDisliked` などで持ち、表示のときに訳す）。
2. ポップアップで言語を変えたら、**開いているミニプレイヤーとページのボタンの説明（title）にもすぐ反映**（今はミニプレイヤーは開いたときにしか文字を入れない）。全タブに反映（R4 の `BroadcastChannel` を使う）。
3. 既定は `auto`（ブラウザの言語）。`popup.html` の `lang="ja"` と初期文字列も切替に追従。
4. テスト: `ja` と `en` のキーが完全に同じであること、`station_hook.js` / `popup.js` が参照するキーが辞書に全部あることを Node で検査。

### R3. 除外（Hate）リストにこの作者が入っているか分かるようにする
表示の案（この形で作る）:
1. **ページの 🚫 ボタンとミニプレイヤーの 🚫 ボタン**: 今の曲の作者が除外中なら、ボタンを塗りつぶしの赤＋説明「除外中（クリックで解除）」にする。押すと解除（今は解除できない＝E5）。除外中でない作者は今まで通り「押すと除外してスキップ」。
2. **作者のプロフィールページ**（`soundcloud.com/<作者>` 以下）: 名前の近くに小さな札「🚫 FreshDig で除外中　[解除]」を出す。除外していない作者には何も出さない（ページを汚さない）。
3. **ポップアップに「リスト」画面**（R6 の「後で聴く」と同じ画面のタブ切替）: 除外した作者の一覧（名前・除外した日）、上に検索欄、各行に「解除 ✕」。件数が多くても重くならないよう、最初は 50 件だけ出して「もっと見る」。
- データ: 今の `dislikedArtists` をそのまま使う（保存場所は変えない）。新しく除外するときは `{ name, permalink, date }` を保存。古い記録で名前しか無いものは名前だけ表示（**一覧を出すために API を呼び直さない**）。
- 解除は新しい操作 `UNBAN_ARTIST`（`ack` で必ず返事）。

### R4. 複数タブで、ミニプレイヤーが今流れている曲にならない
原因: ミニプレイヤーはタブごとに別物で、それぞれ**自分のタブの**プレイヤー表示を写している。音を出しているタブは 1 つなのに、他のタブのミニプレイヤーは止まったタブの曲を出し続ける。
直し方:
1. `BroadcastChannel('freshdig')`（同じ `soundcloud.com` の全タブで使える。拡張の裏側を通さなくてよい）で、**音を出しているタブ**が 0.5 秒ごとの同期のたびに「今の曲」（曲名・作者・画像・再生中か・位置・長さ・Like/リポスト/フォロー/除外の状態・音量）を流す。
2. どのタブのミニプレイヤーも、「最後に再生中を知らせてきたタブ」の情報を出す（自分のタブが再生中ならそれ）。
3. ミニプレイヤーのボタン操作（前・再生/停止・次・Like・👎・🚫・➕・フォロー・音量・シーク）は、音を出しているタブへ `BroadcastChannel` で送り、そのタブが実行する。返事（トースト用）も同じ通路で返す。
4. 音を出しているタブが閉じられたら（`pagehide` で「いなくなる」を流す）、ほかのタブは自分の表示に戻る。
- 送受信の形は `{ type, fromTabId, seq, ... }`。自分が送ったものは無視。タブの見分けは起動時に作る乱数 ID。
- R2 の言語変更、R6・R3 のリスト変更の知らせにも同じ通路を使う。

### R5. 飛ばす曲のスキップを速くできるか
今は「曲が切り替わった通知 → すぐ判定 → 次へ」なので、判定自体は速い。遅く感じる・重いのは、**飛ばす曲も 1 曲ずつ再生を始めて音声を読み込んでから次へ行く**ため。
調べて直すこと（Sonnet が開発者ツールで `getScRequire()` / `findScModule()` を使って SoundCloud の再生待ち行列の形を調べる）:
1. **待ち行列から先に抜く**: 再生待ちの曲（次の数曲）を前もって `getSkipReason()` で判定し、行列から外せるならそこで外す。外せない場合は、次へ進むときに「次に流してよい曲」まで**一気に飛ぶ**（1 曲ずつ `playNext` しない）。
2. 1 が無理なら最低限: 切替通知の `setTimeout(..., 0)` をやめて同じ処理の中で判定し、スキップするときは先に一時停止してから次へ（音の読み込み開始を減らす）。DOM のボタンを押す方法より `playNext` を先に使う。
3. 結果を数字で報告: 「既知の曲が 10 曲続くステーション」で、最初の未知の曲が鳴るまでの時間と、音声の読み込み要求の数（開発者ツールのネットワーク）を、直す前と後で比べる。
- 外せる・飛べるかは SoundCloud の作り次第なので、**調べた結果をまず報告してから**作る（無理なら 2 だけ）。

### R6. 「後で聴く作者」リスト
使い方: 「この曲いいな」→ ボタンで作者を保存 → あとでリストから作者の**投稿曲だけのページ**（`https://soundcloud.com/<作者>/tracks`）を開いて全部聴く → 聴き終えたらリストからワンクリックで消す。
1. ボタン「🎧 後で聴く」を、ページのプレイヤー部分とミニプレイヤーに足す。押すと今の曲の作者を保存（もう入っていれば「入っています」と出して、押すと外す＝切り替え）。
2. 保存する中身: `{ artistId, name, permalink, avatarUrl, addedAt, fromTrackTitle }`。保存場所は `chrome.storage.local` のキー `laterArtists`（SoundCloud のサイトデータを消しても残る。ポップアップは SoundCloud のタブが無くても見られる）。書き込みは `content_bridge.js` の新しい要求 `LATER_ADD` / `LATER_REMOVE` で、**読み出し→変更→保存を 1 か所で**行う（タブ同士の上書き事故を防ぐ）。変更は `chrome.storage.onChanged` で全タブに知らせてボタン表示を更新。
3. ポップアップの「リスト」画面に「🎧 後で聴く」タブ: 新しい順、各行に作者名（押すと `/<作者>/tracks` を**新しいタブ**で開く）・保存した日・きっかけの曲名・「✕ 削除」。
4. **大事**: 作者のページ（`/<作者>`、`/<作者>/tracks`、`/popular-tracks`、`/albums`、`/sets/...`、`/reposts` は除く）から再生しているときは、発掘モードでも「Like 済み」「フォロー中」ではスキップしない（その作者の曲を全部聴きたいので）。曲単位の 👎 と作者の 🚫 だけは効かせる。今の `isExplicitLibraryPage()` を広げる形で。
5. 件数の上限: 500 件（超えたら追加を断って知らせる）。

### R7. 音が途中で聞こえなくなる（気がする）
原因はまだ分からない。**先に記録を取れるようにして、ユーザーに再現してもらう**。
1. 診断ログ: 最新 300 件の出来事を localStorage に輪の形で残す。記録するもの: 音声要素の `pause` / `waiting` / `stalled` / `error` / `ended` / `volumechange`（値と消音）、FreshDig の自動スキップ（理由）、FreshDig が音量を変えた時、自分の API 呼び出しで 200 以外が返った時、ロボット確認の検出、タブの表示/非表示、ミニプレイヤーの開閉。時刻とタブ ID 付き。
2. ポップアップの詳細設定に「📋 診断ログをコピー」。ユーザーは止まったらすぐ押して貼る。
3. 疑わしい原因（ログで見分ける）:
   - H1: ロボット確認で音声の読み込み（細切れの音声ファイル）が 403 になって止まる → R1 と同じ原因。
   - H2: 再生中の曲を後から DOM の Like 表示で「Like 済み」と判定して飛ばしている（`monitorPlaybackWithMargin` の後半）。
   - H3: 別のタブで再生が始まり、SoundCloud が元のタブを止めている（自動ミニプレイヤー・メディアキーが別タブに届いた等）。
   - H4: 音量: 内部の音量モジュールが見つからない時の代わりの処理で `audio.volume` を書いている／消音の切替。**シークバーが進んでいるのに無音なら H4、止まっているなら H1〜H3**。
4. 再現で原因が分かるまでは、推測での修正はしない。ただし H2 は今のうちに直してよい: 曲の途中（再生開始から 5 秒以上たった後）には自動スキップしない。

### R9. ミニプレイヤーを使っていると、元のページの曲名・作者名の表示がおかしくなる
（ユーザーの話の 8 番目は 7 と 9 にまたがっていたので、番号は 9 にしている）
仮説: FreshDig がページ下のプレイヤーの曲名欄（`.playbackSoundBadge__actions`）にボタンを 6 個（約 190px）差し込んでいるので、曲名・作者名の幅が押しつぶされて切れる・ずれる。R6 でボタンが増えるとさらに悪くなる。
1. まず再現してスクリーンショットを撮る（ミニプレイヤーを開く前・開いた後・ボタンを押した後）。仮説と違えば、その結果を報告に書いて止まる（ユーザーにスクリーンショットをお願いする）。
2. 直し方（仮説が当たっていれば）: FreshDig のボタンを曲名欄の外に出す。プレイヤー部分の右側（音量の隣）に FreshDig 専用の小さな枠を作り、よく使う 3 つ（👎・🚫・➕）だけを常に出し、残り（📻・🎧・🪟・🔍）は「⋯」を押すと開く小さなメニューに入れる。SoundCloud 本来の曲名欄には何も足さない。

### R10. 「フレッシュさ」で飛ばす（目立たない追加機能・既定は OFF）
ポップアップの「⚙ 詳細設定」（閉じた状態）の中に置く。
1. 設定項目（それぞれチェックで有効、数値は自由入力）:
   - 作者のフォロワーが **N 人より多い**ならスキップ（初期値 1000）
   - 作者の投稿曲数が **N 曲より多い**ならスキップ（初期値 100）
   - （おまけ）曲の再生回数が N 回より多いならスキップ / 曲の投稿が N 日より前ならスキップ
   ※ユーザーの例「フォロワー 1000 人」は「1000 人を超えたら飛ばす」と解釈。画面の文で誤解が無いようにする。
2. データ: まず曲の情報（`sound.attributes.user`）に `followers_count` / `track_count` が入っているかを調べる。入っていなければ `users/<id>` を取りに行くが、**作者ごとに 7 日間保存**（localStorage、最大 5000 人、古い順に消す）し、R1 の上限を必ず通す。分からないうちは飛ばさない（再生開始から 5 秒以内に分かれば飛ばす）。待ち行列の先の曲を前もって調べられるなら（R5）そこで調べる。
3. 判定は `getSkipReason()` に足す（ほかの規則の後）。理由の表示は「フォロワーが多い作者」など。R6 の作者ページから再生しているときは効かせない。
4. 設定は `chrome.storage.local` の `freshFilter`（`content_bridge.js` の `SYNCABLE_KEYS` に足す）。

## 3. 決まり（守ること）
- `CLAUDE.md`（このフォルダ）の決まりを全部守る。特に: API は `scApi()` だけ、トークンはキャッシュしない、音量は `setSoundCloudVolume()` だけ、`postMessage` は `window.location.origin` へ、要求には必ず `ack`、除外の記録に空のキーを入れない。
- 新しい操作（`UNBAN_ARTIST`、`LATER_ADD` など）も必ず返事をする。
- 保存場所を勝手に移さない（Dislike は今の localStorage のまま）。新しい保存キーは `CLAUDE_REVIEW_GUIDE.md` のデータ一覧に書き足す。
- 権限（`manifest.json` の `permissions`）を増やさない。必要になったら止めてユーザーに聞く。
- ロボット確認を突破・回避する仕組み（自動で解く、偽装）は作らない。
- コミットはこのサブモジュール（`main`）で、フェーズごとに。push はユーザーに確認してから。親の `C:\scripts` 側のサブモジュール参照の更新は最後に 1 回。
- 同じ不具合を 2 回直して直らなければ、3 回目は試さずに止めて Opus に相談（`C:\scripts\CLAUDE.md` §3）。

## 4. ユーザーに聞くこと（実装中に分かったら）
