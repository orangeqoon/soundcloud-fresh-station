# FreshDig v2.3.0

2026-10-24

## 変更した機能

- ミニプレイヤー上段の「後で聴くリスト」は、ミニプレイヤーとは別のウィンドウで開きます。開いている場合はそのウィンドウを表示します。
- 別ウィンドウでは古い順の一覧、検索、保存日、×での解除を使えます。ポップアップ側の一覧も引き続き使えます。
- 日本語の「Dig Config」を「Dig設定」、「診断レポート保存」を「不具合レポート保存」に変更しました。
- ポップアップに「リスト書き出し」「読み込み」を追加しました。
- 対象は「後で聴く作者」「不再生の曲」「作者除外」「ジャンル除外」の4種類です。SoundCloudのLikeやフォロー一覧を変更する機能ではありません。

## 書き出し・読み込みの使い方

「リスト書き出し」から、閲覧用のMarkdownまたは復元用のJSONバックアップを保存できます。**読み込みにはJSONを使います。Markdownは閲覧用です。**

「読み込み」でFreshDigのJSONバックアップを選び、追加件数を確認してから適用します。既存の項目は消さず、同じID・キーの項目は既存データを優先して統合します。保存日も保持します。JSONは最大5MiB、後で聴く作者は既存と合わせて500件までで、超える場合は切り捨てず読み込みを止めます。

除外リストと後で聴くリストの保存先は別です。一部だけ適用・完了を確認できなかった場合は、その旨と再試行を表示します。再試行で重複登録は作りません。

書き出し・読み込み時はSoundCloudタブを開いておいてください。除外リストの正本はSoundCloud側のブラウザーストレージ、後で聴く作者の正本は拡張のストレージです。SoundCloudのサーバーへリストを書き込む操作は行いません。

別タブの通知が届く前でも、書き出し・読み込みの直前に保存済みの除外データを読み直します。ただし、従来の複数タブによるlocalStorageへの完全同時編集は、全体としてトランザクション化されていません。この既存制約は今回の狭い変更では全面的に作り替えておらず、同時編集の実機検証も未実施です。

## SoundCloudへ保存する機能について

JSONバックアップがあれば、**バックアップ目的でSoundCloudのプレイリストへ保存する必要はありません**。ローカルJSONなら4種類をまとめて復元でき、SoundCloudへの通信も増やしません。既存の不再生プレイリスト連携は、使っている人向けの任意の手動機能として残しました。削除はしていません。

## 再生停止の修正

添付レポートを比較し、現行コードでも通信待ちの自動復帰が700ミリ秒で音声を一時停止してしまうケースを再現・修正しました。自動復帰の待機には上限を保ちますが、遅いバッファリングを理由に音声を止めません。不具合レポートには実行中の版、音声状態、復帰結果も追加しました。

古いレポートだけで、実際のすべての停止が同じ原因だったと断定はしていません。詳しい調査は「FreshDig-不具合レポート調査.md」にまとめました。

## 既聴曲モード

今回は実装せず、計画を「FreshDig-既聴曲モード実装計画.md」にまとめました。実再生10秒を初期案とし、曲IDと最小限の情報をIndexedDBへ保存します。全履歴をメモリへ展開せず、直近の固定数だけをキャッシュします。永久に正確な履歴の保存容量は、聴いた曲数に応じて増えます。

## 確認した範囲

指定のNodeテスト33件と追加テスト42件、計75件が合格。UserScriptビルド、構文・JSON・版の一致、差分検査を確認しました。模擬Chrome APIとオフラインの模擬SoundCloudページを使ったヘッドレスEdgeでは、4言語、別リスト画面、スクロール・日付・解除、バックアップ往復、遅延したファイル選択、最新データとの統合、部分失敗の再試行を確認しました。

実際にインストールした拡張機能によるウィンドウ作成・ファイル保存と、実アカウントでの長時間再生は未確認です。ストアへは公開していません。
