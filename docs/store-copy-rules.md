# FreshDigの説明文ルール

README、Chrome Web Store、Microsoft Edge Add-onsの説明は、この文書を正本にします。検索順位を操作するキーワード詰め込みはせず、実装済みの動作を対象ユーザーの課題と結び付けて書きます。

## 共通

- 最初の文で「SoundCloudの何を、誰のために、どう改善するか」を書く。
- 「推薦アルゴリズムを変更する」とは書かず、「SoundCloudが返した候補と再生キューをDig ON時に除外・整理する」と書く。
- スキップ、保存、記録、優先、バックアップ、操作など、確認できる動詞を使う。
- 「100%」「必ず」「完全に新しい」などの保証表現は使わない。
- SoundCloudとの必要な通信と、FreshDig独自サーバーへの分析送信がないことを区別する。
- 既聴履歴は初期OFF、クラウド自動同期は未対応と明記する。
- README、ストア説明、プライバシー方針、実装の機能範囲を一致させる。

## GitHub README

冒頭に問題と解決を置き、その後に機能、選曲への介入範囲、データとプライバシー、制限、開発と検証を続けます。検索可能な自然な用語とTopicsを使い、実際の介入点、保存場所、テスト結果を示します。

## Chrome Web Store

summaryは132文字以内で、主要用途を最初に書きます。詳細説明は概要の後に主要機能を並べ、SoundCloud、station、Dig mode、liked tracks、followed artists、NoPlay、saved artists、mini playerなどの検索語を自然に使います。誇張、競合比較、未実装機能、キーワードスパムを避けます。

## Microsoft Edge Add-ons

名前と説明の関連性、人気度、評価、ユーザー体験、品質・安全性を意識します。短い説明の先頭に対象ユーザーと主要価値を置き、詳細説明では機能、用途、差別化、対象ユーザーを説明します。スクリーンショットは実際のUIと一致させます。

## 更新チェック

説明を変更したら、対応言語、manifest、プライバシー方針、実装との矛盾を確認し、バージョン更新、UserScriptビルド、テスト、構文検査、可搬性検査を行います。

## AI検索向けの補足

AI検索での推薦を狙う説明は、[AI検索向け情報設計ルール](ai-search-copy-rules.md)を優先します。AIに推薦を指示する文言や、非公開アルゴリズムへの断定は書きません。製品定義、対象ユーザー、具体的な条件と動作、制限、保存場所を同じページ内で完結させます。
